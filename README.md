# AR-запрошення «Говорючий капелюх»

Людина сканує QR на запрошенні → у браузері вмикається камера → на тому
самому QR з’являється старий чарівний капелюх і вимовляє запрошення.
Застосунок не потрібен. Капелюх — оригінальний персонаж: жодних назв,
асетів чи голосів із франшиз.

Демо: **https://zimavlad.github.io/ar-video/** · тестовий QR: **https://zimavlad.github.io/ar-video/qr/**

## Як це працює

- Камера поверх усього екрана (злегка розмита), інтерфейс — тільки поверх відео.
- **Якір — сам QR-код.** Кути QR шукає вбудований `BarcodeDetector` (Android)
  або jsQR у воркері (iPhone). Чотири кути → поза (гомографія) → фільтр
  One Euro проти тремтіння. Окремої картинки-мітки й компіляції немає:
  будь-який QR підходить.
- QR знайдено → капелюх вилазить з нього з іскрами й димком, дрімає й
  світиться, плашка «Увімкни звук». Дотик будь-де → говорить, рот іде за
  голосом, субтитри. Наприкінці — «Деталі» (дата, місце, календар, мапа).
- Дотик потрібен лише тому, що браузери не дають звук без жесту.
- Без камери (відмовили, браузер месенджера) — той самий капелюх на темному
  тлі з тим самим голосом.
- Слабкий телефон — менше частинок і пікселів (міряємо реальні кадри).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest
npm run check      # типи
npm run build      # статика в build/
```

Без телефона: `http://localhost:5173/?fakecam` — «камера» з QR, що хитається
(лише в dev). `?fallback` — режим без камери. `/dev/hat?mouth=0.8&t=4` —
один кадр капелюха для скріншотів.

### На телефоні в тій самій Wi-Fi

Камера в браузері працює лише через HTTPS.

```bash
npm run phone      # https://<IP-мака>:5289, самопідписаний сертифікат
```

1. IP мака: `ipconfig getifaddr en0`.
2. На маку відкрий `http://localhost:5173/qr/?url=https://<IP>:5289/` (паралельно `npm run dev`) — це і посилання, і якір.
3. Скануй телефоном → попередження про сертифікат: iPhone «Подробиці → відвідати сайт», Android «Додатково → Перейти».
4. Дозволь камеру, наведи на той самий QR.

## Що де міняти

Усе — в **`src/lib/config.ts`**:

| Що | Де |
|---|---|
| Назва, дата, час, місце, адреса, мапа | `event` |
| Текст реплік (субтитри) | `speech.lines` — тримай таким самим, як у записі |
| Голос | `assets.audio` (файл у `static/media/`) |
| Модель капелюха `.glb` | `assets.hatModel` |
| Тексти інтерфейсу | `ui` |
| Розмір капелюха відносно QR | `tracking.hatScale` |

**Свій голос** (ElevenLabs чи запис): `npm run voice:pack -- шлях/до/файлу.mp3` —
стисне й покладе в `static/media/invite.mp3`. Субтитри самі стануть на паузи
запису, рот піде за гучністю. Промпт для ElevenLabs — `docs/voice-elevenlabs.md`.
Заглушка macOS: `npm run voice`.

**Модель з Blender**: `.glb` у `static/models/`, шлях у `assets.hatModel`.
Висота будь-яка (нормалізується до 1), основа внизу, обличчям до +Z,
морф-таргети `mouthOpen` і (необов’язково) `blink`.

**QR для друку**: `/qr/` на сайті (або `/qr/?url=…` для іншої адреси),
друк з браузера. Біле поле довкола — обов’язкове.

## Деплой

GitHub Actions (`.github/workflows/pages.yml`) на кожен пуш у `main`:
тести → збірка з `BASE_PATH=/<repo>` → GitHub Pages. Секретів немає.

## Відомі межі

- QR має займати помітну частину кадру: з відстані капелюх не з’явиться.
- Глянцевий друк і відблиск екрана заважають розпізнаванню.
- Браузери месенджерів (Instagram, Telegram) часто не дають камеру — тоді
  показуємо режим без камери з порадою відкрити в Safari/Chrome.
